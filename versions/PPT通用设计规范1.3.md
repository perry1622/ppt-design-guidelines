# PPT通用设计规范1.3

> 版本：1.3  
> 整理日期：2026-10-23  
> 公开发布版：已移除个人环境专用的凭据配置步骤，核心设计规则不变。  
> 适用范围：课程汇报、设计调研、研究报告、方案展示等 PPT，以及在 Figma 中制作的同类汇报画框。  
> 本文件整合排版、字体选择、毛玻璃、信息图形化及内容同步要求。通用原则可跨项目复用，不规定固定配色；未指定字号时采用本版默认值。

## 1. 使用方式与优先级

优先级：**用户当前明确要求 → 当前项目约束 → 本规范的通用原则 → 本规范的建议参数 → 技能或模板的默认设置。**

- 用户已确定的配色、字体、封面、位置和内容范围，直接沿用，不因更换技能而重置。
- 技能提供方法，不代替审美判断，也不保证结果自动美观。效果要以实际画面和用户反馈为准。
- 不机械复制本文件中的尺寸和参数。先判断展示媒介、画幅、内容量和观看距离，再做小范围样张。
- 改进目标是内容更清楚、重点更突出、图形关系更明确；不是增加卡片、阴影或装饰数量。
- 后续反馈若与旧规范冲突，采用最新反馈，并同步更新规范，避免被否定的方案再次出现。

## 2. 开始排版前先核对什么

1. **内容源**：确认最新文字、图片、数据、图表和视频在哪里，是否仍在编辑。
2. **成稿目标**：确认文件、页面、画框或幻灯片范围；用户已放置的封面和起点位置要先核对。
3. **已有表达**：识别原稿的流程、箭头、矩形节点、分组、对照、示意图和图片标注。
4. **视觉约束**：确认配色、字体、比例、已有参考和不希望出现的元素。
5. **内容缺口**：区分正式内容、占位内容、批注和操作指令。不要把含义未完成的批注当成正式文案。

已有答案或授权不重复询问。普通对齐、间距和分组调整采用合理默认；只有无法从上下文确定、会改变内容含义或重要结果的缺失信息，才需要澄清。

## 3. 内容忠实与文案边界

### 3.1 不擅自改动事实

- 保留原文的事实、数据、单位、限定条件、研究对象和结论含义。
- “可能”“初步”“待验证”等限定词不能为了简洁而删除。
- 调研照片、量尺、按钮、标识和设施问题属于证据，不能通过裁切或修图改变其含义。
- 原稿写着“符合标准”时，保留其来源属性；排版并不等于重新完成了标准核验。
- 原稿有明显歧义或相互矛盾时，保留出处并指出问题，不自行编造一个确定结论。
- 纯排版任务默认不重写内容。确有必要拆段、拆页或增加说明性标题时，不能扩展原结论。

### 3.2 不添加泛用性装饰文案

**每段文字都应有实际信息功能。不得为了“显得完整”“像专业模板”而添加空泛小字、套话或英文标签。**

| 保留的文字 | 应去掉或避免的文字 |
| --- | --- |
| 真实页面标题、研究结论、必要图例 | 无必要的英文眉题、模板标签 |
| 图片说明、测量数值、单位、来源 | 反复出现但不帮助理解的项目口号 |
| 有实际作用的章节标题或导航 | 每页重复的泛用性页脚 |
| 工作稿中的必要待填写状态 | 仅用于填空白、展示材质的文案 |

- 用户未要求时，不额外添加页码、英文副标题和重复页脚。
- 这不是“所有小字都删除”。必要的来源、图例、说明应保留，并确保能读清楚。
- 不把被删的套话替换成另一句套话。
- 制作方法、设计参数、软件操作和同步说明放在规范或交付说明中，不放到正式页面充当装饰。
- 不为展示毛玻璃、图标或其他效果而临时编造一个标签。

### 3.3 内容未完成时

缺少内容时，保留明确、简洁的待填写位置，或在交付说明中列出缺口。不能把空白模板描述为已经完成的研究。

“待补充”只用于确实尚未完成的工作稿内容；最终汇报前应核对这些位置是否仍应展示。未提供的视频不得被标记为已嵌入或可播放。

## 4. 字体选择与一致性

**优先使用 MiSans；没有 MiSans 时，可以自行选择适合内容、清晰易读的替代字体，不必因此暂停工作。** 项目已明确指定其他字体时，以项目要求为准。

- 根据内容气质、展示场景和中文可读性选择字体，不只追求装饰性。
- 标题、正文和必要说明保持稳定的字体分工；通过字重、相对大小、行距和留白建立层级，不靠频繁混用字体。
- 密集正文优先选择笔画清楚、字形完整的常规字重，避免过细或过度装饰的字体。
- 替代字体应具有完整的所需字符和可用字重；导出后确认没有缺字、意外替换或文字变形。
- 字体选定后，整套汇报保持一致。更换字体时重新检查换行、文字高度、溢出和对齐。
- 写入前核实实际可用字体，写入后回读并导出检查，不能只凭“加载成功”判断。
- 本规范不提供固定配色；字号优先遵循项目明确要求，未指定时采用第 5.2 节的默认值。

## 5. 页面骨架、层级与间距

### 5.1 画幅与网格

没有现成规格时，可从 **16:9、1920 × 1080 的 Figma 画框**开始。已有项目的比例优先。

先建立共同的边界、对齐线和间距节奏，再根据页面内容选择布局。

- 页面边缘保留足够的安全留白，避免文字和关键图形贴边。
- 组内间距相对紧凑，组间间距适度拉开，使关系清楚。
- 标题、关键结论、正文和必要说明通过有限的字号、字重和间距形成主次，遵循第 5.2 节的同页字号数量与默认值。
- 文字密集时，优先拆分、分组或增加细节页，不一味缩小文字。
- 行距与段间距根据实际字形、行长和内容密度调整，避免拥挤或过度松散。
- 在实际展示尺寸和观看距离下核对可读性；转到其他工具后重新检查，不能直接照搬像素或磅值。

### 5.2 同页字号数量与默认值

**同一页 PPT 尽量不超过两种字号；只有同时存在一级标题、二级标题和正文三个实际层级时，才可以使用三种字号。** 这里限制的是字号数量，不是字体家族数量。

用户或项目未明确指定时，使用以下默认值：

| 文本层级 | 默认字号 |
| --- | --- |
| 一级标题 | 40 号 |
| 二级标题 | 32 号 |
| 正文 | 24 号 |

- 只有一级标题与正文时：使用 40、24 两种字号，不为了凑齐三个层级添加二级标题。
- 只有二级标题与正文时：使用 32、24 两种字号。
- 同时有一级标题、二级标题、正文时：允许使用 40、32、24 三种字号。
- 图注、测量值、表格、图例和必要说明应归入现有层级，不随意增加第四种或更多字号。
- 同一层级保持统一，通过字重、位置、间距和分组区别内容，不对每段文字单独调字号。
- 内容放不下时，先调整布局、分组或拆页，不通过不断缩小局部字号制造更多规格。
- 若用户明确指定另一套字号，使用指定值，但仍尽量遵循同页两种、三层级时三种的数量规则。
- 上述“号”是 PPT 中的字号设置；在 Figma 等其他画布中实现时，应按最终 PPT 页面比例统一映射并记录对应关系，不把像素数与 PPT 字号混为一谈。

### 5.3 层级要有主次

- 每页先确定一个主要关注点，再安排辅助证据和补充说明。
- 大小、字重、颜色、位置至少有明确的主次差异，但不要求每页都使用全部手段。
- 不让所有文字同样粗、所有图片同样大、所有区块同样抢眼。
- 最重要的元素应在第一眼容易找到，而不是装饰块最醒目。
- 总览页负责呈现全貌，细节页负责解释证据；两者不必使用同一种密度。

### 5.4 留白与节奏

留白应帮助分组、建立阅读方向和突出重点。避免内容只挤在一角，其余空白没有作用。

同一份汇报应统一字体、色彩和对齐逻辑，但不必每页都采用“标题 + 左图右文”。相邻页面可以根据内容形成不同的疏密和主次关系。

## 6. 图形化表达：优先继承原稿

### 6.1 已有图形时

**原稿已有初步图形化展示，尽量在其基础上使用相似的可编辑图形工具重排版。**

应保留：

- 流程方向和先后顺序。
- 分支、汇合、循环、包含和分组关系。
- 矩形节点、箭头、对照栏、图例等已有表达类型。
- 节点与说明之间的对应关系。
- 对信息含义有作用的视觉编码。

优先调整：节点大小、对齐、间距、文字层级、标注位置、连线走向和整体密度。

不要为了套用新风格，把原有关系图改成普通列表；也不要随意把蛇形流程换成直线流程、把双向关系画成单向箭头。确需改变结构时，先确认信息关系不会被改变。

### 6.2 原稿缺少图形时

**原稿没有图形化结构，且信息量较小时，优先选择图形化排版，而不是默认使用纯文字列表或简单左右分栏。**

先识别信息之间的顺序、分类、对照、组成或对应关系，再用简洁的图形组织内容。图形化可以是节点与连线、图标与标签、并排对照、主图与局部标注，不等于为每条信息加框。没有真实关系时，不强行添加箭头、圆环或虚构数据。

根据内容关系选择工具：

| 内容关系 | 可选表达 | 约束 |
| --- | --- | --- |
| 连续步骤、用户动线 | 节点 + 箭头、线性或蛇形路线 | 顺序、起点和终点明确 |
| 同一主题的多个维度 | 中心辐射、并列结构、分类关系图 | 不暗示不存在的先后、循环或因果 |
| 不同对象／状态的差异 | 并排对照、比较矩阵 | 对照维度一致 |
| 部件、空间或设施构成 | 结构拆解、局部标注、图像对应 | 标注位置与对象匹配 |
| 问题与改进 | 对照图、问题—措施对应 | 明确区分现状证据和设计建议 |
| 测量与判断 | 实拍证据 + 数值、单位、局部标记 | 数值必须来自原始材料 |
| 层级、包含或分类 | 树形结构、层级图 | 无依据时不制造优先级 |
| 多张调研照片 | 主图 + 细节、证据组、素材索引 | 不把所有图片都缩成同等小图 |

图形必须解释关系。不能为了“丰富”而加入无信息的圆环、箭头、图标或虚构统计图。

### 6.3 图标与线条

- 图标只表达确切的对象、动作或类别，不作无意义填充。
- 同一套图标保持相近的线宽、圆角、视角和复杂度。
- 箭头方向有含义，不能只为构图好看。
- 节点与连线应避开文字和关键照片细节。
- 图标含义可能不明确时，配必要的真实标签；不要求观众凭图猜测。

## 7. 照片、证据与图文关系

- 先确定哪张照片解释主要问题，再安排辅助图片。
- 可使用主图配细节、横向证据组、并排对照、照片与测量标注等构图。
- 不同信息量的照片不必等大；但不能为了变化而故意打乱阅读顺序。
- 同一结论对应的照片和文字要靠近，避免观众跨页或跨远距离寻找对应。
- 证据照片优先完整显示；裁切前检查是否会丢失量尺、按钮、标识、高差等关键信息。
- 图片不得拉伸变形。保留比例，必要时用留白或调整容器形状适配。
- 局部放大应能看出其与原图的关系；不能放大到看不出上下文。
- 实拍资料与生成示意图应明确区分，生成内容不得伪装成真实调研记录。

## 8. 表格与密集信息页

- 表格保留明确列名、稳定列宽和一致的行关系。
- 优先使用浅色表头、细分隔线、适当行距，避免粗重网格。
- 列宽按内容量分配，不机械等分。
- 长内容优先换行或拆页；不要首先缩小字号。
- 总览图与详细表可以并存，但分别承担“看关系”和“读细节”的功能。
- 比较项中的限定词、数值与单位完整保留。
- 不为了图形化而把更适合精确比较的表格改成难以阅读的装饰图。

## 9. 毛玻璃与其他材质：少量、轻透、可取消

### 9.1 使用边界

- 毛玻璃只在小部分真实内容位置尝试，不是每页必备元素。
- 正文、照片、表格和每个段落不需要套进框。
- 可从每页 0–1 处局部效果开始；这是控制用量的建议，不是配额。
- 材质必须让位于内容，不遮挡证据、不降低文字清晰度。
- 当前默认方向是透白、低浓度底色、浅灰轻投影。

### 9.2 已弃用方案

**不再采用“实心浅杏底 + 棕色投影 + 多重内阴影”的厚重组合。** 用户已指出其灰暗、发棕且不美观，不得把它继续当作默认推荐参数。

不能仅通过加深阴影、加大模糊、增加卡片数量来解决层次不足。

### 9.3 轻透参考参数

以下来自当前 Figma 修订样式，可作为试做起点；不是所有页面都应使用的固定标准，也不代表用户已确认其适合所有场景。

| 项目 | 参考值 |
| --- | --- |
| 参考载体 | 1000 × 126 px 的目录标题区域；尺寸随内容调整 |
| 圆角 | 22 px |
| 白色垂直渐变位置 | 0% / 45% / 100% |
| 对应填充不透明度 | 88% / 64% / 82% |
| 描边 | 白色，90% 不透明度，1 px |
| 背景模糊 | 20 px |
| 外投影 | 采用适合当前项目的浅色轻投影；不透明度及强度以不形成脏边为准 |
| 内阴影 | 不使用 |
| 可选底色 | 继承当前项目主题，保持低浓度与轻透感，不固定色值 |
| 文字 | 与当前项目保持一致，独立保持清晰；不随底板一起降低不透明度 |

### 9.4 透明度与工具差异

**不透明度 = 100% − 透明度。** 例如 83% 透明度对应 17% 不透明度，不是 83% 不透明度。

- 原参考图的软件参数只作视觉参考，不直接照搬到 Figma 或其他软件。
- 字号、磅、像素、渐变角度和模糊参数，要按目标工具的实际效果核对。
- 不把网页饱和度当成图层不透明度。
- 背景模糊作用于玻璃底板，不给文字或整组内容添加模糊。
- 纯白背景上效果可以很轻，不需要为了“看出玻璃”而制造脏边。
- 效果不好或导出不一致时，退回白色或浅色纯底；不为保留材质牺牲阅读。

### 9.5 从按钮规范可借鉴的内容

可借鉴单底板结构、柔和圆角、细描边和轻微层次。旧按钮规范的蓝色、其他字体、手机按钮高度、悬停和按压效果不自动迁入静态 PPT。

## 10. 素材生成与工具选择

### 10.1 先判断是否需要生图

优先顺序：已有可信素材 → 原生可编辑图形 → 确有必要的生成素材。

简单流程、节点、箭头、图标和表格，优先使用 Figma／PPT 的可编辑工具。需要插画、纹理、氛围背景或概念视觉时，再考虑生图。不要为使用某个技能而把整页可编辑内容转成图片。

### 10.2 生图约定

- 内置生成工具可用且适合当前任务时优先使用。
- 内置工具不可用、确有需要时，可使用操作者已授权的图像生成服务或兼容 API；先核实端点、模型、权限和费用，不猜测可用能力。
- 使用服务提供者支持的凭据配置方式；不要复用不适用于该用途的登录凭据，也不要绕过工具权限或访问限制。
- 凭据仅在必要调用时使用，不写入提示词、公开仓库、普通脚本、聊天记录或日志。
- 未确认可用的接口、配额和生成结果，不描述为已成功。
- 尽量让生成素材不包含正文文字；标题、正文、数据和图注使用项目选定字体在编辑工具中排版。
- 保留不含敏感信息的提示词、输出位置和用途说明，方便复用。

## 11. 技能分工

依据实际操作选技能，不是技能越多越好。先读必要的说明，再按其适用范围使用。

| 技能 | 用途 | 使用边界 |
| --- | --- | --- |
| figma-use | 读取、编辑、回读 Figma 节点 | 不代替内容和视觉判断 |
| presentation-design | 组织汇报重点、观点和证据 | 不机械套模板，不覆盖已定字体与配色 |
| critique-visual-hierarchy | 检查视觉落点、阅读顺序和权重 | 输出可执行修改，不以泛泛评价代替修正 |
| baoyu-infographic | 信息图布局与风格参考 | 原工作流偏图片生成；当前任务需要可编辑图形时，取其构图参考并使用原生工具 |
| baoyu-slide-deck | 幻灯片版式、图形组合和整套节奏参考 | 不默认把可编辑成稿换成整页图片 |
| imagegen | 确有必要的栅格素材生成 | 不用来替代已有真实照片或简单可编辑图形 |
| find-skills | 当前方法不足时查找相关技能 | 阅读正文、核对来源和依赖，不因名称或热度就安装 |

同名技能只读一份。新技能的默认字体、配色、卡片风格和提问流程不能覆盖当前用户已经明确的要求。

## 12. 原稿、成稿与后续同步

### 12.1 分清来源与输出

内容源与排版成稿分别管理。原稿继续更新时，以用户指定的最新来源为准，不把早期复制件当成永久事实。

可采用“原稿页／成稿页”的组织方式，但具体页名、位置和文件由项目决定。本规范不绑定某一个文件或节点 ID。

### 12.2 保存可维护的对应关系

需要后续同步时，在项目工作文件中记录源节点、成稿节点及必要的内容快照。不要把这些技术信息放到汇报画面上。

- 更新前比较源内容、上次快照和当前成稿。
- 源内容与成稿都被修改时，保留双方内容，识别冲突，不能盲目覆盖用户手动改动。
- 拆分后的文字应按实际语义重新定位；源文本结构变化时，不能只照旧行号替换。
- 新增或删除照片后，重新检查分组、尺寸和留白，不只删除一个节点就结束。
- 来源更新后检查相关标题、正文、图例和图片说明是否一致。
- 同步说明要明确本次核对的范围；保存了映射不等于已经启动后台自动同步。

### 12.3 工作状态要说准确

区分：本地准备、实际写入、回读核验、导出检查、保存状态确认。只有相应步骤完成后，才能声称该部分已完成。

### 12.4 完成后解组与直接编辑

**每一页完成并检查后，解散内容分组（Ungroup），便于用户直接选中文字、图片和图形。** 此规则适用于后续所有 Figma 排版任务，无需每次重复确认。

- 制作过程中可以使用临时分组；交付时移除不必要的 GROUP 和妨碍直接编辑的内部嵌套。
- 保留用于页面管理与导出的最外层画框，不把解组理解为删除整个页面结构。
- 保持文字为原生可编辑文本，图片和图形仍可独立选择；不能用转曲、扁平化或合成整页图片代替解组。
- 自动布局 FRAME 与 GROUP 不同。内部自动布局若只是制作辅助、交付后不再需要，应在保持位置和视觉效果的前提下简化；不要无差别拆除有实际功能的结构或分离组件实例。
- 解组前后核对绝对位置、尺寸、叠放顺序、遮罩、裁切和效果；不能因方便选择而破坏画面。
- 组级透明度、遮罩或效果无法直接保真时，先采用保留可编辑性的处理方式；确实无法兼顾时说明具体限制，不默默把内容栅格化。
- 直接编辑检查还包括字体实际可用：原生文本未锁定不等于用户必然能编辑，缺失字体也要处理。

## 13. 执行流程与验证

1. **读取与核对**：确认最新来源、目标、位置、字体、已有图形和约束。
2. **确定版式**：已有图形时优先继承；没有图形且信息量较小时优先采用图形化排版，并找出真正需要强调的内容。
3. **做代表页**：先完成有代表性的文字页、照片页或关系图，导出检查后再扩展。
4. **分批写入**：小步完成、回读受影响内容；避免一次性改完整份后才发现基础样式有问题。
5. **检查内容**：核对原文、数值、单位、图片对应、箭头方向和待补充状态。
6. **检查视觉**：字体、同页字号数量、默认字号或项目指定值、溢出、重叠、裁切、对齐、层级、图形标注和材质。
7. **检查整套节奏**：统一而不机械重复；重点页有焦点，总览与细节密度有区别。
8. **解组与编辑检查**：每页完成后解散不必要的内容分组，保留最外层画框；复核位置、效果和文字实际编辑状态。
9. **交付与停止**：确认实际写入及保存状态，给出文件位置和必要说明；检查通过且没有新问题后停止，不自行追加重构。

授权范围内的可恢复编辑直接完成。样张检查是质量控制，不自动变成每一步都要求用户重新批准的流程。

## 15. 本版整合记录

本版按最终确认的要求统一了以下规则：

- 字体优先使用 MiSans，不可用时可自选合适替代字体；不规定固定配色。
- 同页尽量不超过两种字号，完整三个文本层级时可使用三种；未指定时默认一级标题 40 号、二级标题 32 号、正文 24 号。
- 每页完成并检查后解散不必要的内容分组，保留最外层画框和原生可编辑对象。
- 只借鉴旧按钮规范中适合静态汇报的结构和层次方法。
- 毛玻璃少量使用，弃用灰暗、厚重、发棕的方案。
- 不添加“看起来像模板自动生成”的泛用性装饰文案。
- 丰富层次应依靠内容关系、图形和证据组织，而非不断加框。
- 原稿已有图形时优先使用相似工具进行重排；没有图形且信息量较小时优先采用图形化排版。
- 原稿持续更新时保留同步能力，并保护用户手动修改。
- 素材生成遵循现有授权与实际工具能力，凭据不泄露。

整合依据：设计协作中的排版反馈、材质试验及内容同步实践。公开版保留设计原则，移除了个人环境和凭据读取步骤；未包含未发布的项目素材。
